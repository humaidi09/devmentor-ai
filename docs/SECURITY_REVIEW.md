# Close AI Phase 6 security review — 2026-10-13

**Scope:** repository code, disposable local PostgreSQL/GoTrue/PostgREST account stack, built browser bundles, configured demo website and current cloud API access. This is an implementation review, not a penetration test or verified hosted audit. The older FastAPI service is retained but is not called by Close AI; its mock tests were run separately.

| Area | Evidence and finding | Remaining risk / action |
| --- | --- | --- |
| Authentication | Local signup, signin, signout, session persistence, private-route redirect and unauthorized API tests passed. Server middleware and private APIs call Supabase `getUser`; ownership comes from the verified session. Signup input, password length, redirect paths and same-origin mutations have negative tests. | Hosted email confirmation, expiry, account switching, cookie flags and Auth configuration remain untested. No account mode is live. |
| RLS and authorization | Fresh migrations `0001`–`0009` applied locally. Catalog query found RLS enabled on all 32 public tables. Two test users and maintainer/reviewer accounts could not cross private profile, saved, plan, reminder, notification or learning boundaries. Composite ownership constraints and role separation passed. | Repeat on the selected hosted project after migrations. A local fixture is not proof of hosted grants or legacy data compatibility. |
| Resource verification | Local tests exercised draft/submission/checked verification, audit events, immutable DEMO flag and edit downgrade. Student cannot grant staff roles or fabricate events; reviewer notes remain staff-only. Search rejects expired, wrong-campus and unverified records for trusted grounding. | No real campus record or named reviewer has been checked. Fictional seed records cannot support a real pilot. |
| AI grounding and prompt injection | Model sees only current message and small retrieved resource summaries. Output is restricted to selected IDs/allowlisted step keys; server renders database-authored facts and unknown fields. Tests rejected fabricated IDs/URLs/actions, malicious retrieved instructions, malformed/rate-limited/timeout provider responses and unsafe high-risk routing. A real Gemini request with fictional context passed validation. | Keyword safety routing is limited and the tested Gemini model is preview. Human review of real pilot prompts and provider terms is still needed. |
| Consent and user control | Support saves/draft plans need explicit storage consent and approval. Notification schedules need explicit approval and opt-in; Codeforces preview does not store a handle until confirmation. RLS and own-data reset were tested. | Full Auth-user deletion is operator-assisted, not self-service; a hosted operator deletion/retention test is required. No real feedback owner exists. |
| Secrets and logging | 53 built browser bundles contained no AI/service-role secret binding names or configured secret values. Web code has no prompt/profile `console` logging. No service-role key is used by the Close AI web app. | Provider, platform and Auth operational logs and retention have not been audited. Do not copy key values into reports or tickets. |
| Input and abuse control | Routes use bounded JSON parsing, strict field/ID/URL/enum validation, verified session and origin checks. AI and Codeforces use durable user/hour budgets; Codeforces also caps response size, sample size and request spacing. Negative tests passed. | Supabase Auth/platform throttles need hosted review; no distributed global Codeforces queue. |
| Browser and session headers | Phase 6 added `nosniff`, frame denial, restrictive frame/object/base CSP, referrer and permissions headers. Local HTML and API responses carry them; private account responses are `no-store`, and demo worker excludes API/user data. Auth/demo cookies use HTTPS-dependent `Secure` and Lax SameSite in code. | Full script/style CSP with nonces and hosted cookie behavior are unverified; repeat header/cache checks on deployed account pages. |
| Dependencies | `npm audit --omit=dev` reported **1 high** (`postcss`) and **1 moderate** (`next`) advisory; full dependency tree reported 8 high/3 moderate, largely build tooling. npm reported no safe automatic fix for the production pair. No user-authored CSS or source maps are processed by the app, which limits the relevant PostCSS attack surface. | Track targeted upstream patches and reassess before pilot; do not force a major upgrade during final QA. This is an open dependency finding, not a clean audit. |
| Deployment access | Demo website reported `mode=demo`, `supabaseConfigured=false`, revision `951efe4`. Supabase Management API returned 401; Vercel token authenticated but project/team access returned 404/403. | Hosted migrations, production variables, Auth redirects, monitoring, backup and restore remain unverified. They block pilot deployment. |

**Release decision:** no local cross-user or privileged-secret leak was found in the executed checks. The pilot remains blocked by hosted configuration, unverified real resources and human ownership, deletion/restore evidence, and the open dependency review. A small internal test against the disposable fixture is appropriate.
